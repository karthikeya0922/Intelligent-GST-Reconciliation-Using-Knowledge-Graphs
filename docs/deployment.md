# Production Deployment Runbook

## 1. Overview

The platform deploys as three independent services, all on free tiers:

| Component | Host | Notes |
| --- | --- | --- |
| Frontend (React/Vite) | Vercel | Static build, Hobby plan |
| Backend (FastAPI) | Render | Web service, free plan, auto-deploys from `main` |
| Database (MongoDB) | MongoDB Atlas | M0 free cluster |
| Knowledge graph (Neo4j) | *not deployed* | Graph endpoints report offline and degrade cleanly |

The backend degrades gracefully at every layer: without Atlas the Mongo-backed
routes fail but `/risk/*` keeps serving, and without Neo4j the graph endpoints
report `connected: false` while everything else works.

---

## 2. Backend (Render)

### 2.1 Service configuration

* **Build command:** `pip install -r requirements.txt`
* **Start command:** `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`

### 2.2 Environment variables

| Key | Required | Value |
| --- | --- | --- |
| `MONGODB_URI` | Yes | Atlas SRV connection string (section 3.3) |
| `PYTHON_VERSION` | No | `3.11.6` if pinning is desired |

> **`render.yaml` is not applied to services created through the Render
> dashboard.** It only takes effect when the service is created as a Blueprint.
> A service created manually ignores the file entirely, so both `MONGODB_URI`
> and `PYTHON_VERSION` must be added by hand under **Settings → Environment
> Variables**. The symptom of missing this is the backend falling back to the
> `localhost:27017` default in `backend/main.py` and every Mongo route
> returning 500.

### 2.3 Dependencies worth knowing

`pyarrow` is mandatory. pandas does not bundle a parquet engine, and both
`backend/ml/data_store.py` and `backend/ml/risk_engine.py` read
`data/processed/*.parquet`. Without it every `/risk/*` route raises
`ImportError` and returns 500 in well under a second. It is declared in
`backend/requirements.txt`; note that `requirements-data.txt` is a separate
file that Render never installs.

## 3. Database (MongoDB Atlas)

### 3.1 Cluster

Create an **M0 (free)** cluster. The free tier is limited to one per project,
and Atlas hides the option once it is used — create a new project if M0 is not
offered. The paid M10/M30/Flex tiers on the default template page are not
required; 512 MB is ample, since only seeded vendors, invoices, alerts and
users live in Mongo. The 46,345-row feature dataset is read from parquet on
the backend's own disk and never touches the database.

### 3.2 Network access

Add `0.0.0.0/0` to the **IP Access List**, not a specific address. Render's
free tier has dynamic egress IPs, so there is nothing stable to allowlist.

The Atlas "Connect" wizard allowlists only the current machine's IP, which
makes a connection string work locally while failing from Render. Leave the
"temporary entry" toggle off, or the rule self-deletes and the backend breaks
hours later.

Access remains protected by SCRAM authentication; the allowlist is a second
layer, not the only one.

### 3.3 Connection string

From **Database → Connect → Drivers → Python**:

```
mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?appName=Cluster0
```

* `<password>` is the **database user's** password, not the Atlas account login.
* URL-encode any of `@ : / ? # [ ] %` in the password (`@` becomes `%40`).
  Autogenerated Atlas passwords are alphanumeric and avoid this entirely.
* No database name is needed in the path — `backend/main.py` selects
  `gst_reconcile_ai` explicitly.

### 3.4 Seeding

None required. On the first successful connection, `seed_data()` and
`seed_gst_ecosystem()` populate an empty database with vendors, invoices,
alerts and two user accounts, and `migrate_plaintext_passwords()` rehashes any
legacy credentials.

Seeded accounts (**change these before any non-demo use** — they are published
in this repository):

| Email | Password | Role |
| --- | --- | --- |
| `admin@gstreconcile.ai` | `admin123` | admin |
| `auditor@gstreconcile.ai` | `auditor123` | auditor |

## 4. Frontend (Vercel)

Set `VITE_API_URL` to the Render service URL in **Settings → Environment
Variables**. Vite inlines this at build time, so it must exist before the build
runs, and changing it requires a redeploy rather than a restart.

If it is unset, the bundle falls back to `http://localhost:8000`, every request
fails, and `DataContext.jsx` silently serves bundled mock data from
`src/data/mockData.js`. The dashboard renders fully populated either way — see
section 6.

To confirm what a deployed build is actually pointing at:

```bash
curl -s https://<app>.vercel.app | grep -oE '/assets/index-[A-Za-z0-9_-]+\.js'
curl -s https://<app>.vercel.app/assets/index-XXXX.js \
  | grep -oE 'https?://[a-zA-Z0-9.-]+\.onrender\.com|http://localhost:[0-9]+'
```

## 5. Verifying a deployment

```bash
B="https://<service>.onrender.com"
for p in "/" "/risk/summary" "/api/risk/vendors?limit=1" "/api/model/info" \
         "/api/graph/status" "/api/vendors" "/api/invoices" "/api/alerts" \
         "/api/reconcile"; do
  printf "%-32s %s\n" "$p" "$(curl -s -o /dev/null -m 90 -w '%{http_code} %{time_total}' "$B$p")"
done
```

All routes should return `200`. Then confirm authentication is hitting Mongo
rather than the client-side fallback:

```bash
curl -s -X POST "$B/api/login" -H "Content-Type: application/json" \
  -d '{"email":"admin@gstreconcile.ai","password":"admin123"}'
```

A correct password returns `{"success":true,...}` and a wrong one returns
`{"success":false,"error":"Invalid email or password"}`. A `500` on **both**
means Mongo is unreachable — the handler fails before comparing anything.

## 6. Free-tier behaviour

**Cold starts.** Render free instances spin down after ~15 minutes idle. The
first request then takes ~50s to wake the container, plus ~12s for
`RiskDataStore` to build its in-memory cache. Subsequent requests are
sub-second. Because `DataContext.jsx` treats a failed fetch as "API offline"
and loads mock data, a cold start can present as a working dashboard showing
fabricated numbers.

**Keeping the backend awake.** `.github/workflows/keep-backend-awake.yml` pings
`/` every 10 minutes so the service never idles out. It targets `/` because that
route touches neither MongoDB nor the parquet store, and keeping the process
alive also preserves the in-memory caches. Actions minutes are free on public
repositories.

Two caveats. Render allows **750 instance-hours per month per workspace** and a
month is ~730 hours, so keeping one service awake around the clock consumes
almost the entire allowance — adding a second free service will exceed it.
Narrow the cron expression (for example `'*/10 2-18 * * *'`, roughly 08:00-24:00
IST) if that headroom is needed. Separately, GitHub disables scheduled workflows
after 60 days without repository activity, and delays scheduled runs under load;
the 10-minute interval is set well inside the 15-minute idle window to absorb
that drift. A dedicated uptime monitor such as UptimeRobot or cron-job.org keeps
stricter time if reliability matters more than staying in-repo.

**Memory.** The data store settles at roughly 258 MB RSS — 152 MB after the
parquet loads, 243 MB after the first `/risk/summary`, plateauing near 258 MB
once all 23 periods are cached. That fits the 512 MB free limit with headroom,
and the per-period cache plateaus rather than leaking.

**Ephemeral disk.** `data/reports/ml/risk_assessment_audit.log` is written at
runtime and is lost on every spin-down and redeploy. Route it to external
storage if an audit trail needs to survive restarts.

**Silent fallback.** Three distinct failures — unset `VITE_API_URL`, a
cold-start timeout, and an unreachable database — all present identically as a
fully rendered dashboard containing mock data, with only a `console.warn`.
Never judge deployment health from the rendered UI; check the API directly
using section 5.

## 7. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `/risk/*` returns 500 in <1s | `pyarrow` missing; pandas has no parquet engine | Ensure `pyarrow` is in `backend/requirements.txt` |
| `ServerSelectionTimeoutError: localhost:27017` | `MONGODB_URI` not set; using the default | Add it under Settings → Environment Variables |
| `ServerSelectionTimeoutError: <cluster>.mongodb.net` | Render's IP not allowlisted | Add `0.0.0.0/0` to the Atlas IP Access List |
| Mongo routes hang ~30s before failing | Driver's default server-selection timeout | `MongoClient(..., serverSelectionTimeoutMS=5000)` |
| Auth failure despite a correct password | Unencoded special characters in the URI | URL-encode, or regenerate an alphanumeric password |
| Dashboard shows data but it is wrong/static | Frontend fell back to `mockData.js` | Verify the API directly (section 5) |
| Graph panel reads offline | Neo4j is not deployed | Expected; point `NEO4J_URI` at an Aura instance to enable |

Startup diagnostics are printed to the Render log — search for
`MongoDB not reachable`, which reports the host actually attempted.
