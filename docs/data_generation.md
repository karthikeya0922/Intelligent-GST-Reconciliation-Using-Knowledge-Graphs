# Synthetic GST Generation & Behavioral Profiles

> [!NOTE]
> **Data Provenance Notice**  
> The system uses a hybrid dataset consisting of publicly available transaction data and controlled synthetic GST-specific records. Public data provides realistic transaction distributions, while synthetic data introduces GST-specific filing, reconciliation, ITC, and compliance scenarios that are not available in most public datasets.

---

## 1. Architectural Philosophy

Synthetic GST records are not generated by drawing random noise. Instead, generation is driven by **vendor behavioral profiles** that simulate real-world taxpayer traits: filing habits, accounting system errors, fraudulent patterns, and transaction volumes.

---

## 2. Behavioral Profile Specifications (A–H)

| Code | Profile Name | Target % | Characteristics & Compliance Behavior |
| :--- | :--- | :--- | :--- |
| **A** | **Compliant Vendor** | ~58% | Strict on-time filing (delay $\le 0$ days), error-free arithmetic, 100% e-Invoice and e-Way Bill compliance. |
| **B** | **Occasional Mismatch** | ~14% | Low-to-medium mismatch rate (3–8%), occasional 1–3 day filing delay, sporadic typographical or rounding errors. |
| **C** | **Chronic Mismatch** | ~6% | High mismatch rate (25–40%), frequent arithmetic discrepancies, persistent 10–30 day filing delays. |
| **D** | **Late Filer** | ~8% | High invoice accuracy, but chronic and substantial filing delays (15–45 days past statutory deadlines). |
| **E** | **Missing-Return Vendor** | ~4% | Issues invoices booked by buyers in Purchase Register, but repeatedly fails to file GSTR-1 or GSTR-3B. |
| **F** | **High ITC Exposure** | ~4% | Substantial ticket sizes (5x–20x population average, ₹5,00,000–₹50,00,000); compliant but creates systemic exposure. |
| **G** | **Suspicious Network** | ~3% | Collusive entities operating in dense circular invoice loops ($V_1 \rightarrow V_2 \rightarrow V_3 \rightarrow V_1$) to fabricate artificial ITC. |
| **H** | **Duplicate Generator** | ~3% | Generates intentional exact duplicates and near-duplicates (suffix `/A`, 1-day date shift, penny rounding) to test entity resolution. |

## 3. Anomaly Engine & Statutory Discrepancies

Controlled anomalies are injected using `backend/data/synthetic/anomalies.py`:

```text
TAX_MISMATCH                Supplier declares tax diverging from calculated slab
TAXABLE_VALUE_MISMATCH      Base value discrepancy between supplier and buyer
MISSING_GSTR1               Invoice absent from supplier sales return
MISSING_GSTR2B              Invoice not auto-populated in buyer 2B
MISSING_GSTR3B              Supplier filed GSTR-1 but defaulted on GSTR-3B (unpaid tax)
HSN_MISMATCH                Inconsistent 4-8 digit HSN/SAC classification
DATE_MISMATCH               Invoice date crosses filing month boundary
DUPLICATE_INVOICE           Exact invoice re-submitted for duplicate ITC claim
NEAR_DUPLICATE_INVOICE      Fuzzy duplicate with suffix or 1-day shift
MISSING_EINVOICE            Mandatory B2B invoice lacks IRN
MISSING_EWAY_BILL           Consignment value > ₹50,000 lacks e-Way bill
LATE_FILING                 Filing past statutory deadline (11th for 1, 20th for 3B)
UNUSUAL_TRANSACTION         Anomalous spike in invoice velocity or ticket size
```

---

## 4. Multi-Period Temporal Simulation & Determinism

The pipeline supports generating arbitrary continuous tax periods (default: 12 months, e.g. `2024-04` through `2025-03`).

### Seed Determinism
When executed with the same random seed, the generator guarantees identical, byte-for-byte outputs:
```bash
python -m backend.data.pipeline --vendors 100 --months 12 --seed 42
```
Outputs are fully reproducible for scientific benchmarking, audit reviews, and continuous integration.
